## 개발 전략: 세로 슬라이스
spec §18-7에 따라 레이어별이 아닌 **사용자 흐름 단위**로 끝까지 관통한다.

```text
슬라이스 A: API 설정 → 텍스트 Daily 대화 → 피드백        (음성 없이 핵심 루프 검증)
슬라이스 B: A + 음성 입력(STT) + 음성 출력(TTS)          (발화 지표 측정 시작)
슬라이스 C: 나머지 5개 모드 + 테마/역할 설정
슬라이스 D: 최초 진단 → 레벨 → 홈 KPI → 기록/복습
```

## 주요 위험과 대응
| 위험 | 영향 | 대응 |
|---|---|---|
| Mac에서 Windows 빌드 불가 | Windows 회귀를 늦게 발견 | 매 push마다 GitHub Actions windows 빌드, 주요 마일스톤마다 사용자 PC에서 실행 |
| STT→LLM→TTS 왕복 지연이 큼 | 대화 몰입 저하 | LLM 스트리밍 + 문장 단위 TTS, "생각 중" 상태 표시, 텍스트 폴백 |
| 진폭 기반 VAD 오탐 | 발화 지표 왜곡 | 지표에 신뢰도 필드, 필요 시 Silero VAD |
| 데스크톱 secure storage 불가 환경 | 키 저장 실패 | 세션 한정 모드 (S8) |
| API 비용 | 사용자 부담 | 사용량 이벤트 기록, 가격표 확보 전 "정보 없음" |
