# 보안·개인정보 불변식

spec §9.2, §10.2, §13에서 도출. **검사 방법** 열은 이 규칙이 어떻게 강제되는지를 나타낸다.

| # | 불변식 | 검사 방법 |
|---|---|---|
| S1 | API 키는 OS secure storage에만 저장. SQLite·SharedPreferences·파일·백업 금지 | arch_lint(DB 스키마), 단위 테스트 |
| S2 | 키·토큰·음성·대화 원문은 로그/크래시 리포트/분석에 남기지 않음 | print 금지 lint, redacting logger 테스트 |
| S3 | 저장소에 실제 키 커밋 금지 | PreToolUse 훅 + secret_scan + CI |
| S4 | 음성 원본은 기본 미저장. 저장 옵션은 명시적 동의 + 암호화 | 통합 테스트(세션 후 임시 파일 없음) |
| S5 | 키 삭제 시 저장소와 메모리 참조 모두 제거 | 단위 테스트 |
| S6 | 대화 내용은 시스템 정책을 바꾸는 지시로 취급하지 않음 (프롬프트 인젝션) | PromptComposer 테스트 |
| S7 | 측정하지 않은 점수/비용을 생성하지 않음 | 리뷰 + FeedbackService 테스트 |
| S8 | secure storage를 쓸 수 없는 데스크톱 환경 → 경고 후 세션 한정 사용 | 수동 QA |
| S9 | 브로커는 장기 키를 앱에 재노출하지 않음, 요청 바디·헤더 마스킹 | 브로커 테스트 (Phase 2) |

## 키 생명주기
입력(마스킹된 필드) → 연결 테스트 → `CredentialVault.write(ref)` → DB에 `vault_key_ref`만 저장 → 요청 시 vault에서 읽어 헤더에만 사용 → 교체/삭제 시 vault 삭제 + 메모리 해제.

## 사용자 고지 (온보딩 S01)
- 대화 텍스트/음성이 선택한 외부 공급자로 전송된다는 사실과 범위
- ChatGPT/Claude 웹 구독과 API 과금은 별개
- 데이터 로컬 저장 위치와 삭제 방법
